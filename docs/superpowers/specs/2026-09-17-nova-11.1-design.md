# NOVA 11.1 — stabilization design

## Goal

Prepare a safe NOVA 11.1 release from the current `main` state, preserving the existing panel features while making AWG 3.1 behavior consistent, CI reliable, and VPS updates reversible.

## Scope

1. **Single AWG 3.1 profile**
   - Make `nova_awg31_fix.py`, `nova_diagnostics.py`, Strong Mobile, and generated client configs use the same source of truth.
   - Use one explicit profile with `Jc=4`, `Jmin=40`, `Jmax=120`, `S1=S2=S3=S4=16`, `H1=1`, `H2=2`, `H3=3`, `H4=4`, header protection enabled, `RandomTrailers=on`, `DisableCookies=on`, `MTU=1280`, and the existing timer ranges.
   - Validate that live `awg show awg0` agrees with the file configuration.
   - Do not silently change the existing `ListenPort`.

2. **Diagnostics and tests**
   - Remove the current diagnostics expectation of `S2=24` and `S4=32`; diagnostics must validate the shared profile instead.
   - Make diagnostics testable without requiring a pre-existing SQLite `clients` table.
   - Add focused tests for AWG profile consistency and diagnostics page/API behavior.
   - Keep real-server checks guarded so CI does not require AWG, iptables, systemd, or a real network.

3. **Updater safety**
   - Replace the current update flow's unconditional service mutation with preflight → backup → install → compile/tests → AWG validation → service validation.
   - Preserve the current `/opt/awg31-panel` runtime layout.
   - Keep a rollback path for panel/AWG configuration failures.
   - Do not require Telegram/nginx to be running for the core panel update; report optional service failures explicitly.

4. **Web-panel hardening**
   - Keep the existing authenticated UI and features.
   - Remove insecure default Flask secret behavior when practical; require a generated/persisted secret on install rather than a public fallback.
   - Convert state-changing HTTP actions to POST where they are currently GET-based and add a lightweight CSRF mechanism for authenticated forms/actions.
   - Do not expose private keys or the header-protection key in normal rendered/downloaded client-facing pages unless explicitly requested by an authenticated administrator.

5. **Telegram v2 branch**
   - Do not merge the existing PR #1 as-is because its merge commit currently fails two tests.
   - Rebase/fix the Telegram work after the core NOVA 11.1 test contract is stable.
   - Preserve the existing self-service bot behavior and add admin/status/routes functionality only after CI passes.

## Architecture

The release keeps the current modular structure rather than performing a large rewrite. The shared AWG profile becomes the boundary between configuration generation, migration, and diagnostics. Diagnostics consume that profile and add live-server checks. The updater orchestrates deployment and rollback but does not contain AWG parameter definitions.

## Failure handling

- Configuration migration writes a timestamped backup before mutation.
- If AWG restart or live validation fails, restore the previous configuration and restart the previous service state.
- If panel installation fails validation, do not claim a successful update.
- Optional integrations (Telegram, nginx) are reported separately from core panel health.

## Verification

CI must pass Python compilation/import tests, shell syntax checks, pytest, and the existing Android/Windows workflows where applicable. Release readiness additionally requires a clean diff review and a safe VPS update command that runs the repository updater only after the branch is merged.

## Out of scope

No redesign of the NOVA UI, no new VPN protocol, no automatic VPS access from ChatGPT, and no forced change of the production UDP port.
